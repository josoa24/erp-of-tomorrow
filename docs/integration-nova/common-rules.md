## Code rules (CLAUDE.md + docs/REGLES_DEVELOPPEMENT.md)
- Reuse existing components/services/hooks before creating. 100 lines max per file (code, tests, CSS). One responsibility per file. Explicit names.
- NO COMMENTS in produced or modified code (no `//`, `/* */`, `#`, JSDoc, `<!-- -->`). Express intent with names, structure and tests. Keep pre-existing comments outside the modified scope.
- Front layering: `services/api/*` pure HTTP (one file per resource) -> `services/*` pure logic -> `hooks/*` state + errors (useApiError) -> components (display only) -> screens (assembly). Feature code goes in `novaui/src/features/<module>/{api,services,hooks,components,screens,types}` or the existing top-level folders for shared code. No fetch/API call or business logic in components.
- Errors never in popup/toast/inline red text: they route to the dedicated error page via useApiError. Toasts are success-only. Field-level validation hints BEFORE submit (required, format) are allowed as helper text; server errors go to the error page.
- Validated data is immutable: no edit/delete controls on validated records; corrections are new writes.
- Hide what the role cannot use (nav, actions); the server must also enforce it.
- TypeScript strict, `import type`, no enums, no `any`. cva variants in separate `*-variants.ts` files. Token classes only (no hex in components). French UI copy, fr-FR Intl formatting, currency "Ar".
- Back (Spring Boot 3.4, Java 17): Reader/Creator/Updater/Deleter services behind interfaces, thin controllers, DTOs only (never entities), mapper classes, `@Valid` + jakarta validation, centralized `@RestControllerAdvice` with typed errors (`VALIDATION`, `NOT_FOUND`, `BUSINESS`, `IMMUTABLE`, `FORBIDDEN`, `SERVER`), constructor injection, `@Transactional` on writes, validated entities immutable (409 IMMUTABLE), historical entities have no updater/deleter. Same package layout as the existing service.
- Every new logic has unit tests (AAA, one behaviour per test, names `shouldX_whenY`, nominal + error cases). Front: Vitest + Testing Library in `__tests__/` next to the file. Back: JUnit 5 + Mockito, `@WebMvcTest` for controllers. Keep coverage of new services/hooks >= 80 %.

## Database
- Persistence uses Hibernate `ddl-auto: update` (no Flyway). Schema evolutions must be compatible with existing populated databases: new columns nullable or with a DB default, new tables, no destructive change. For each schema change also write an idempotent SQL migration script `docker/postgres/migrations/<NNN>_<service>_<description>.sql` (ALTER TABLE IF EXISTS ... ADD COLUMN IF NOT EXISTS, CREATE TABLE IF NOT EXISTS, constraints with explicit names, backfill UPDATEs for existing rows) so the change can be applied and reviewed explicitly; number it with the prefix given in your brief. SQL files are code too: no `--` comments in them. Report cardinality, FK, nullability, constraints and backfill rationale in your final output (`migrations` field), not in the files.
- Hibernate 6.6 creates CHECK constraints for `@Enumerated(STRING)` columns and `ddl-auto: update` does NOT update them when you add an enum value: any new value of an existing enum needs a migration that drops and recreates that check constraint (find its real name in pg_constraint; write it idempotently). Never add a NOT NULL column without a DB default to an existing table.
- The Maven cache must not be `~/.m2` created by Docker as root: use `-v <SCRATCH>/m2:/root/.m2` (shared cache, already warm) and run Maven in the worktree, then remove the root-owned `target/` it creates with `docker run --rm -v <dir>:/w alpine rm -rf /w/target` so no root-owned files stay in the worktree.
- Machine is small (4 CPUs, ~5 GB free): check `uptime`; if the 1-min load is > 8, wait (e.g. `timeout 60 tail -f /dev/null`) before starting a Maven build or a stack.
- Cross-service references (different schemas) cannot be physical FKs: store the id (and a display snapshot if needed) and validate existence through the owning service API with the caller's X-User-* headers.
